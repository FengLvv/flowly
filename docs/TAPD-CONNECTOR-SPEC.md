# Tencent internal TAPD inputs

User decision, 2026-11-13: integrate `tapd.woa.com`, use the user's existing MCP access to discover examples. This extends [CONNECTORS-SPEC](CONNECTORS-SPEC.md); its read-only, artifact ownership, cache, unread and card/session authorization rules still apply. Native project and workspace scope stays [single-root](SINGLE-ROOT-SPEC.md).

## Connection and transport

- Provider `tapd-internal`, family `tapd`. One connection names one TAPD project: `https://tapd.woa.com/tapd_fe/<workspace_id>`. A detail/list URL may be pasted in Settings; save normalizes it to that project root. Reject other hosts, protocols, credentials, ports and missing project IDs. Project IDs and 19-digit item IDs remain strings.
- This provider uses the fixed, already configured **tapd** MCP server through the host's installed `mcporter` or `@tencent/mcporter-internal` Node runtime. It is an explicit transport extension to the HTTP-only adapters, not a public `tapd.cn` API integration. No token field and no credential copying: authentication stays in the host's existing MCP configuration. Test/save checks the project is in `user_participant_workspace_get`; it never silently picks a project.
- The daemon resolves the installed runtime from PATH, launches Node using an argument array with a fixed bridge program, and passes JSON as an argument. No shell, configurable command, endpoint, tool name or arbitrary tool arguments from the client. Run from the host home, not a card repository. Failure and child stderr never expose configuration, URLs containing credentials or tool output. Missing runtime/server, login failure, timeout and malformed responses fail with actionable English errors.
- Fixed read-only whitelist: `user_participant_workspace_get`, `user_todo_stories_get`, `user_todo_bugs_get`, `user_todo_tasks_get`, `tapd_id_get`, `stories_get`, `bugs_get`, `tasks_get`, `comments_get`. The three todo calls require exactly the configured `workspace_id`; the client cannot omit or override it. Validate tool parameters, project, object type, pagination and IDs before dispatch. No discovery/write tools at runtime. Bound calls to 20 seconds, process to 25 seconds, output to 4 MiB; always close the MCP runtime. No background polling beyond existing visible connector reads.

## Item contract

- Requirements, bugs and tasks use existing `itemType` values `story`, `issue`, `task` (the last is added to the enum). Canonical keys include the project and kind: `tapd:<workspace_id>:<story|bug|task>:<id>`; canonical artifacts always use the returned **19-digit** ID, preserving precision and avoiding collisions across TAPD projects and other connectors. IDs remain internal identities, not display text.
- Recognize internal `.../tapd_fe/<workspace_id>/<story|bug|task>/detail/<19-digit-id>` and list/iteration URLs with `dialog_preview_id=<story|bug|task>_<19-digit-id>`. The configured project must match exactly. Legacy detail URLs `/<workspace_id>/prong/stories/view/<id>` and `.../bugs/view/<id>`, `.../tasks/view/<id>` are also accepted on the internal host.
- Picker accepts links, canonical keys, `story-123`, `bug-123`, `task-123`, and bare short/19-digit IDs. Bare IDs search all three kinds; a short ID is resolved with `tapd_id_get` for its kind. No blind concatenation or conversion of long IDs to Number. Explicit keys, links and numbers always resolve within the configured project regardless of the picker filter, so a user can import another person's work item deliberately.
- The picker defaults to **My to-dos**, with **All work items** as an explicit alternative. My to-dos means the current host MCP account's pending requirements, bugs and tasks as defined by TAPD, not all historical assignments. Empty and title queries use the three `user_todo_*_get` calls with the configured project. Filter out valid rows from other projects if TAPD returns them; missing project IDs or malformed item IDs fail as invalid data. Title matching is literal, case-insensitive and applied to the returned todo names/titles before the result limit (10 recent / 20 search). An unavailable or refused todo endpoint is an error with Retry; never silently show everybody's items or report a partial list as complete. All work items keeps the existing project recent/title search. User text is never raw TQL/queryToken execution.
- Fetch exactly the requested project/kind/ID and validate returned project and ID. Empty search is empty; missing exact items are EXTERNAL_NOT_FOUND. Permission/auth errors are EXTERNAL_AUTH; missing tools/runtime and transient errors EXTERNAL_UNAVAILABLE; invalid project/link/key or malformed data EXTERNAL_INVALID. Empty comment responses are allowed only when explicitly reported as no data; unknown errors must not masquerade as empty results.
- Preview and `flowly_read_external` include title, description converted from HTML when needed, status, priority, owner, modified time and up to 20 comments. External state is reference only. Content fingerprints use title, description and comment ID/body/timestamp, excluding status/owner. Comment changes are checked even when the parent modified time is unchanged.

## UI and import

- Settings → Connections → TAPD: project address and optional name; explain the existing host MCP dependency and read-only access. Artifacts → + → TAPD work item, paste-link recognition, preview, New task → From TAPD, and agent reads reuse existing connector paths.
- Both picker entry points show the compact My to-dos / All work items control for recent and title queries. Exact-key/link/number lookup hides the filter. Reuse the validated `connectors.search.all` boolean: absent/false selects TAPD My to-dos, true selects All work items; other providers keep their existing semantics. Include the filter in the client query key to isolate result/error/loading states, and reset it when the picker closes. No account setting, new RPC field, persisted preference, polling or additional client data table is needed.
- User decision, 2026-11-16: TAPD picker rows and selected chips show only the work item's title, without key/ID, type, status or time. The linked artifact row and preview modal title hide an exact stored canonical-key prefix, including existing artifacts; custom titles remain intact. Do not show TAPD ID badges on the card face or IDs in selection/removal labels and success toasts. Preserve internal keys, references, deduplication, URLs and stored titles; other connector presentation stays unchanged. User notes and the non-obvious warning about another card already using an item remain. This display-only refinement needs no new onboarding tip/tour text, translation key or telemetry field.
- New task imports the selected TAPD title using the existing untouched-title rule. On creation, when the user has left Description empty, import the first selected TAPD item's description on the daemon **before** provisioning a workspace. Never overwrite a nonempty user description, and never import comments as the card description. Other providers keep their behavior. Errors refuse creation before any native resource exists.
- All changed strings go in every catalog. Add TAPD to the tour's existing inputs row and README and add a one-time `tapd-connect` tip when a card is open (the Artifacts + entry is visible). Its copy points out the default My to-dos and All work items option. The filter is visible at both entry points and does not warrant a second tip or tour section. No new setting/action telemetry field: this transient lookup scope is covered by existing connector counts; never transmit project IDs or ticket content.

## Acceptance

UI verification uses an owned isolated host and session. Capture privacy may hide other project tabs only; it must not hide toolbar actions or the board. The runner proves navigation remains usable after capture, selects TAPD rows by their accessible title, and keeps private ticket titles/bodies out of exported evidence. New-card import, artifact linking/preview/deduplication and session-authorized external reads are separate checks.

1. Add/test/save/remove a project-scoped TAPD MCP connection without tokens reaching the client; existing stored connections remain readable.
2. Links, exact keys, short/long IDs, recent and title search support requirements/bugs/tasks with collision-free keys and no cross-project reads.
3. New-card title/description import, artifact recognition, preview and scoped agent reads work; body/comment changes mark unread, external status never moves a card.
4. Read-only whitelist, argument validation, missing runtime/auth/empty/error/timeout handling and bounded output are covered by focused checks; typecheck and existing connector tests pass.
5. Live internal MCP discovery/read is recorded without private ticket content; desktop/compact UI and installed-plugin checks, failed and unrun checks are reported separately. Test resources are owned and cleaned up; the persistent infinite canvas is not reloaded.
6. Both entry points start on My to-dos, switching All and back isolates results, and title matching occurs before truncation. Cover requirements/bugs/tasks, foreign-project rows, empty to-dos, failed endpoints, explicit lookup of another person's item, unchanged other connectors and strict read-only todo arguments. Desktop and compact checks exercise the installed RPC and UI; no message is sent and no daily project/card data is changed.
7. TAPD rows/chips/artifact labels show titles without IDs or automatic metadata. Existing artifact prefixes are hidden without stored-data writes; custom titles, internal references and duplicate detection stay intact. Verify actual desktop/compact rendering and successful selection/import.
