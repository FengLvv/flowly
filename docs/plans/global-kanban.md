# Flowly 全项目总看板规划

状态：规划稿，2026-11-16。尚未实现、安装、重载或发布本功能。

## 1. 已确定的方向

用户本轮已选择：

1. 第一版汇总**所有 Flowly 项目的卡片**，不把未绑定的 Paseo 会话自动变成卡片。
2. 默认按**待处理、运行中、待查看、其他**分列。

范围是当前 Paseo host 下的 Flowly 项目，不做跨 host 聚合。总看板是现有卡片的跨项目视图。一张卡仍属于原项目，仍对应原工作区，其会话、工具范围、原生资源归属和业务阶段均保持原契约。运行状态与业务状态分别表达：会话结束不是卡片 Done，已读不是验收完成。

## 2. 参考项目核查

用户输入：better-paseo 仓库链接及本轮截图。截图只用于分析，没有复制到仓库。

研究固定到 better-paseo `main` 的提交 `f7a17a707b8abbb62cb725bdfbed8d2474bb830e`，并实际阅读了 README 和相关源文件，而非只照截图猜功能。

| 手动折叠泳道、折叠条计数、空分组控制 | 复用 Flowly 的折叠交互，补充总览自己的分组状态 |

| 卡面显示项目/工作区、模型、运行时间、子会话摘要；详情复用 | 总览卡片增加清晰的项目来源，复用 Flowly 卡片/会话详情和现有卡面设置 |
| 窄屏与手机有各自的布局处理 | 遵循 Flowly 当前以可用宽度为准的 compact 规则，不复制参考项目的设备分流 |

## 3. 入口、导航与卡片

### 入口

- 项目 tab 行最左侧增加固定的**总览**入口，与各项目 tab 并列。它不能拖拽排序，不占用真实 project ID，也没有项目设置/删除菜单。
- 首次进入优先总览；之后在本次 app 运行中恢复最后访问的总览或项目。明确的卡片/工作区深链仍优先。实施时更新 PROJECT-TABS-SPEC 的旧冷启动规则。
- compact 项目选择器增加“总览”；已有项目列表、排序和管理继续保留。
- 在总览打开某卡，只让详情使用该卡的真实项目，底下仍是总览。返回恢复筛选、横向位置、当前泳道和列表位置。另有明确“打开所属项目”动作。

### 卡片

- 顶部展示项目名，必要时带工作区名；主体保持卡片标题。业务阶段作为独立标记，使用该项目自己的泳道名称。
- 会话行显示运行/等待/未读等聚合信息、提供方/模型及必要的子会话计数；多会话不复制成多张卡。
- 复用现有 Card display 设置；总览必需的项目来源不能被误当成当前项目名省略掉。单项目看板保持其现有紧凑布局。
- 点卡片打开 Flowly 详情。只有一个需要处理的会话时，可提供现有的直达会话动作；多个会话需明确选择，不能任意发送给其中一个。
- 创建卡片前必须选真实项目，之后才进入原表单、取项目默认设置并创建工作区。总览自身不创建原生项目或工作区。

## 4. 分组规则

以下是同一卡片的优先级，顺序从上到下，每张可见卡片只出现一次：

| 分组 | 判定 | 默认排序建议 |
| --- | --- | --- |
| 待处理 | 未解决的权限请求、代理问题、错误、失败/不可用的自动审查，或卡片明确处于 Blocked | 严重程度优先，再按等待时间最长优先 |
| 运行中 | 无更高优先事项，且至少一个会话在 running/initializing，或自动审查正在运行 | 当前持续运行最久优先 |
| 待查看 | 无更高优先事项，存在有效未读结果，或卡片业务阶段是 In review | 最新结果/审查时间优先 |
| 其他 | 尚未启动、空闲、已读后继续等待等未完成卡片 | 最近更新优先 |

- 一张卡同时有“一个会话运行、另一个等批准”，归待处理，仍显示运行计数。
- Done/Cancelled 卡片若仍有上述实时事项，仍出现在相应关注列，带原业务阶段标记；不能因为业务完成就隐藏仍运行/待批准的会话。
- 没有实时事项的 Done/Cancelled 进入可开启的“已完成”历史区；归档卡片/项目只在显式历史筛选下只读显示，不混入默认活跃集合。历史区默认折叠。
- 已完成历史提供 24h / 7d / 全部，建议总览默认 7d，只影响历史卡片；未完成卡片不因太久未更新被自动隐藏。沿用 finishedAt 等明确完成事实，不拿任意 updatedAt 冒充完成时间。
- 继续遵循现有已读 token、手动未读、子会话和自动审查抑制规则。子代理正常结束不新增用户未读，权限/错误仍可提醒；自动审查期间被暂缓的未读不能提前露出。
- Dismiss 仍只暂不处理其当前信号，不代表已读或业务完成。被暂不处理的会话提醒不再把卡片单独顶到提醒列，可带标记回到其运行中/其他分组；显式 Blocked/In review 的业务待办不因已读或 Dismiss 被修改。新信号恢复提醒。实施前为这组交互补充明确的统一派生测试。
- 数据加载/失败必须区别于零。保留可用缓存并标记过期；无可信实时输入时显示未知状态，不呈现“全部正常”。
- **关注列禁止拖动改状态**。原项目业务看板仍支持左键拖动；总览可从卡片菜单修改真实项目允许的业务阶段，但不能跨项目搬卡或改变工作区归属。

## 5. 泳道宽度和滚动

第一期采用每个视图内统一列宽，建议：

- 紧凑 280 pt、标准 320 pt、宽 400 pt，另有自定义 240–600 pt 和重置。
- 新总览默认 320 pt；现有单项目视图保留原来的 280 pt，避免更新后已有布局突然改变。两种视图分别记忆设置。
- 可用空间不够时横向滚动，不把列压成难读的窄条。打开详情、折叠列或窗口缩放，必须重新测量内容边界并约束滚动偏移。
- 每列可以手动折叠为窄条，仍显示名称和数量；提供一键折叠/展开空列。运行时不能因为计数变零就擅自改变用户的折叠选择。
- 保留本轮已交付的空白处右键平移，以及底部滚动条默认/平移时隐藏、底部悬浮时显示的行为。
- 手机/compact 仍为单泳道列表和切换控件；不把固定桌面列宽套到手机屏幕。宽度控件隐藏，但持久化值不被覆盖。
- 第一版先通过列宽菜单和数值设置完成。逐列独立宽度、拖拽边缘调宽放第二期；指针调宽必须即时跟手，释放后才保存，不能每一帧写 RPC。

以上数值是本规划的建议值，不是参考项目已有的逐列自定义能力，也不是已实现的 Flowly 设置。

## 6. 筛选、排序和信息量

第一期保留常用操作，避免复制截图中的全部控件挤满一行：

- 搜索标题、已有描述及项目/工作区名称；不为搜索预下载每个会话的完整历史。
- 常用筛选：项目多选、标签、提供方/模型。更多面板：优先级、类型、真实业务阶段、工作区。
- 同一维度多选为 OR，不同维度为 AND；提供方/模型必须由同一符合条件的会话满足，不能拼接两个不同会话的属性误匹配。
- 筛选 chip、当前匹配数量、清除筛选和空结果恢复入口；可区分项目本来没有卡片与被筛选后为空。
- 默认采用第 4 节的关注顺序；还可按项目、更新时间、优先级、标题排序。总览不写入新的跨项目手动 position，不改变单项目内排序。
- 已完成范围独立于实时事项，不把等待批准、运行中或未读结果因时间窗口排除。
- 复用现有卡面显隐/密度，不新增另一个大而独立的卡片设置系统。精确逐秒计时只更新可见卡片；时间自然流逝不应触发整板重新排序。

## 7. 技术落点与边界

已核实的复用基础：

- `shared/overview.ts` 的 BoardOverview 已包含 projects/tasks/cards；`client/queries.ts` 已有按 host 共享的 Overview 和 live agent 查询。
- `shared/attention.ts` 本来就在所有活跃项目间计算 Attention，`shared/session-attention.ts` 已定义已读、错误、等待和子会话规则。
- `client/board.tsx` 当前将列表和详情绑定到一个选中项目，需要拆开“看板范围”和“详情所属项目”。
- `client/geometry.ts` 当前将列宽固定为 280；`client/columns.tsx` 已测量布局并支持右键平移，可参数化复用。
- `client/lane-list.tsx` 已有宿主 FlatList 方案；不能把跨项目大量卡片简单塞进目前桌面完整 map 渲染路径。

建议实施结构：

| 层次 | 规划改动 |
| --- | --- |
| 范围/导航 | 显式 `BoardScope = {kind: "all"} / {kind: "project", projectId}`；详情目标独立保留 taskId/projectId/workspaceId |
| 派生模型 | 独立 GlobalLane 类型，不复用业务 Status；纯函数生成每卡唯一分组、原因、排序键和数量，复用现有 Attention 规则 |
| 展示 | 新增轻量总览容器，复用卡片、详情、会话操作、筛选组件及列几何；不要继续把所有分支堆入 BoardContent |
| 列宽 | 移除展示层对固定常量的依赖，集中处理首尾边界、折叠、右键平移和原项目业务拖拽命中 |
| 设置 | 扩展宿主 `board-view`，给总览单独的列宽、折叠、项目筛选、排序和历史范围字段；旧字段和旧单项目设置保留 |
| 权限/写入 | 继续使用原 RPC；每次动作按真实项目/卡片/工作区/所选会话 fresh 授权，缓存和总览筛选不构成授权 |

- 第一版不需要创建“总览项目”、改项目/工作区绑定、改卡片状态存储或新增全局写接口。
- 宿主设置沿用 daemon 保存及冲突合并；不复制参考项目的 localStorage、sessionStorage 或私有原生模块。
- 先复用现有总览增量/etag和共享流，不能为每个项目各轮询一份，也不从客户端建立第二个 Paseo 连接。
- 总览关闭或被 compact 详情覆盖时，按现有规则暂停不可见工作。每列虚拟化，稳定 key 和 memo 回调；隐藏/返回保留输入与滚动位置。
- 实施前测量大量项目和卡片下的现有 Overview payload。若现有描述字段成为瓶颈，再按实际证据设计更小投影；不在规划阶段凭空引入第二套重复数据协议。

## 8. 分期与验收

### 第一期：可日常使用的总览

范围：固定总览入口、四类关注分组、项目来源、原卡详情、三档/自定义统一列宽、手动折叠、项目/标签/提供方筛选、基础搜索与排序、折叠的历史区、紧凑布局及性能边界。

实施顺序：先冻结分组/已读/Dismiss/自动审查契约 → 分离 scope 与详情导航 → 列宽参数化及虚拟化 → 接入总览 → 筛选设置与新用户说明 → 独立验证。

必须通过的验收：

1. 至少三个项目同时显示，卡片唯一且来源准确；选择/返回卡片保持总览上下文。无多建、重绑、自动导入原生资源。
2. 多会话并发、等待与运行重叠、未读/已读/手动未读、代理问题、子会话、自动审查、Dismiss、新信号恢复、业务终态仍有运行事项等分类符合表格；业务状态不被派生分组改写。
3. 列宽、折叠、筛选持久化并可恢复/重置；窗口、详情和多客户端冲突后仍可用；现有单项目宽度、左键拖卡、右键平移、底部滚动条规则无回归。
4. 原有会话发送目标、fresh 授权和精确已读代次保持；加载/失败不报零，无自动全部已读、批量批准或误发消息。
5. 在 1/10/50 项目与 100/500/2000 卡片样本上记录初显、滚动/切列和返回详情性能；总览不挂载全部不可见卡片、不下载全会话历史，也不新增按项目轮询。具体性能阈值在实施前基线测量后冻结，不能以感觉替代数据。

验证流程：类型检查、相关与全量测试分别记录；独立 Haiku 5.5 在精确提交上验证；桌面与 750px 实际宿主 UI、手机手势和必要的性能基线分开记录。仅使用明确自建 fixture，保留用户日常数据和画布，截图用项目 shot-lib，清理仅限本次创建的资源。

需要同步的规范：UI-UX、PROJECT-TABS、SESSION-ATTENTION/ATTENTION-DISMISS、CARD-DISPLAY、PERFORMANCE、ONBOARDING。新增可发现的总览入口应更新欢迎引导及一次性 `global-board` 提示，所有新 UI 文案补齐目录；不在功能任务写 What's new 或版本号。实施时决定是否将总览入口加入既有心跳统计，不能增加项目名/卡片标题/筛选内容等遥测字段。

### 第二期：在一期稳定后增强

- 逐列宽度与边缘拖拽，保留统一宽度及一键重置。
- 命名保存视图，例如“我需要处理”“特定两个项目”“测试中的卡片”；先做视图配置，不改变任务归属。
- 可切换的跨项目业务阶段视图。不同项目的泳道启用/别名/顺序需要单独约定，不能把某项目的布局默认为全局标准。
- 更细的模型筛选、会话摘要、显式全文搜索和更大历史集合的真实分页，以实际性能/使用证据决定。

不并入本规划：自动接管未绑定 Paseo 会话、跨项目移动卡片、批量 Stop/批准/全部已读、自动编排、替换宿主聊天渲染、自动 AI 改标题。它们不属于用户本轮确认的总览范围。

## 9. 本轮交付边界

本轮只完成参考代码核查、用户范围确认和规划。没有修改产品实现、存储、RPC、设置目录或运行中的插件；没有执行产品测试、安装/重载、创建测试项目/会话或推送本规划。后续按用户确认进入一期实现时，再把上面的契约转为正式 SPEC 和实现验收。
